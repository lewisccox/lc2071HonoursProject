# ATSyRA Nuclear Power Threat Analysis System
A threat modelling tool developed for cyber-security threat analysis of Nuclear Power Plants (NPPs) using goal reachability computation. The project models key case studies from real life NPP cyber-security incidents. Included case studies that are modelled the 2007 Stuxnet attack and 2014 Korean Hydro Nuclear Power attack. 

## Installation 
### Core Functionality 
The project was developed using ATSyRA Studio 3.2.0 which can be [installed here](https://atsyra2.irisa.fr/studio/packages/releases/3.2.0-SNAPSHOT/) (ensure you install the SDK version so all functionality is available). Once ATSyRA Studio is installed you can clone the repository into it by following the steps described in [this tutorial](https://github.com/maxkratz/How-to-Eclipse-with-Github), you now have everything installed!
### Installs for Optional Visualisation
If you wish to use the visualisation system to generate images of NPP models you will need to install Java 11 or Newer (Java 18 was used for development) which can be downloaded and installed either from [this site](https://www.oracle.com/uk/java/technologies/downloads/) or via your system's package manager. If using Windows then a version of GraphViz (the graphics library used for certain diagrams in plantuml) is preinstalled in the PlantUML package which comes included in this repository, if using Linux or MacOS you will need to install GraphViz separately following the steps [described here](https://plantuml.com/graphviz-dot).

## Usage 
There is the possibility to either create your own NPP instances or to perform threat analysis of the defined case studies, this section will give guidance as to how these work in the system.
The working directory for the Nuclear Power Plant threat model is the directory "NPP ABS files"
### Computing Goal Reachability using the Example Case Studies
To perform threat analysis via goal reachability computation, right click on a goal file (the goal files for the provided example case studies are "StuxnetAttackerGoals.abs" and "KHNPAttackerGoals.abs") and then select ATSYRA ABS -> Compute Scenarios (by GAL) from the dropdown menu, from here select a goal that you would like to compute the reachability for this will then generate a report (which is a breakdown of which behaviours were triggered and what state changes they caused) and a plantUML representation in the form of a .dot file created in the doc-gen folder, this can be compiled at https://www.plantuml.com/plantuml/uml/SyfFKj2rKt3CoKnELR1Io4ZDoSa70000 to generate an attack tree.  
### Creating NPP Instances 
To create an NPP instance, duplicate the NPPInstanceTemplate.abs and rename it to your desired filename,  you should define Assets (components within a NPP) and their attributes as well as the relationships between them. Relationships are defined with links i.e. "link AssetA to Asset B as AssetAType::AssetALinkType". Refer to NPPDomain_def.abs to for the definitions of each component and their attributes and references (the types of links that are accepted).
### Creating NPP Behaviours
To define NPP behaviours, duplicate the NPPBehaviourTemplate.abs and rename it to your desired filename. Modify the import statement at the top, changing the text that says "your NPP instance file here" to the name of the instance file you created.  Behaviours can then be defined in the form of guarded actions, which have a guard (asks "if the system is in this state i.e. Reactor.online == false") and an action (change the system to be in this state i.e Reactor.online.assign(true)). Multiple guards can be chained together using AND (&&) and OR (||) expressions. An example guarded action is included in the template to give a demonstration of the syntax.
### Creating Goals for Threat Analysis 
Finally to perform threat analysis on your defined NPP model, duplicate the NPPGoalTemplate.atg file found in the "NPP ABS files" directory and rename it to your desired filename, change the highlighted references to Instance and Behaviour files to the filenames of the Instance and behaviour files you created. In this file goals are defined, goals consist of a precondition (references attributes of different assets to ask if the environment is in this state i.e. if controlCenter.infected == false && reactor.online == true) and a postcondition (references attributes of assets to ask is there a sequence of behaviours that lead to the environment being in this state i.e. controlCenter.infected == true and reactor.online == false), there is an example goal you can refer to for a demonstration of the syntax for defining a goal. you can then follow the process described in the "Computing Goal Reachability" Section to compute scenarios and attack trees for these goals. 
### Visualisation Methods
When an NPP instance is defined, ATSyRA automatically creates a diagrammatic PlantUML representation of it, the system enriches this representation with sprites specific to the context of NPPs and then compiles the plantuml file into an image. To use this functionality, Linux and MacOS users can run the script "createDiagram.sh" in the lc2071HonoursProject/doc-gen/plantuml/ directory, Windows users can use it by running the "createDiagram.ps1" script in the same directory (in both instances you should ensure java is added to your PATH environmental settings in your shell configurations). Upon running the scripts you will then have a diagrammatic representation of whichever NPP you specify saved to the file NPPModel.png.
